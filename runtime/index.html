Night Light VJ

Phase 1

写真の輝度マップに応じて、写真そのものの明るさをKICKに連動させて上げ下げする。個別の光点は打たず、クラスタ分けも無い最小構成。カメラは固定。

Scene

写真を読み込むと、輝度の高い場所（ネオン等）から輝度マップを自動生成する（下の Auto Extract 参照）。 画像はブラウザ内だけで処理され、どこにも送信されない。

Auto Extract（輝度マップの自動生成）

top %（明るい上位何%をマップに含めるか）15.0

検出: -

画素ごとに直接、輝度をそのまま重みにしてマップに書き込む（塊検出はしない）。 クラスタ分けは無く、マップ全体がKICKトラックのNote Onに連動して一律に明滅する （config/midi-mapping.json の name="KICK" のトラックを見る。 無ければ cluster_trigger 全体をKICK扱いにする）。 mask-editor/ で作った points.json を下の欄で読み込むと、 自動抽出の代わりにその点群からマップを作る。

MIDI Input

Web MIDI へのアクセスを要求しています…

Kick Envelope

実際にNote Onを受信したのと同じ処理を呼ぶ（velocity=100）。SEQTRAKが無くても、 MIDI受信側の問題か描画側の問題かを切り分けられる。これを押してメーターだけ動いて 画面が変化しなければ描画側、これでも画面が変化するのに実機のKICKで変化しなければ MIDI受信側（config/midi-mapping.jsonのchannel/noteが実機と不一致等）を疑う。

Brightness

bright gain（明滅の強さ）1.20
base level（待機中の沈み）0.00

輝度マップの値が乗っている場所だけ、MIDIノートに応じて元の写真の明るさを上げる （マップが0の場所は写真のまま変化しない）。base level をマイナスに すると、マップが乗っている場所は待機中は元の写真より暗く沈み、KICKが来たときだけ そこから明るく持ち上がるようになる（0なら待機中は写真のまま静止）。 ambient breathing（MIDIが無い間の自動揺らぎ）は検証を単純化するためいったん オミットしている。

Bloom

strength1.60
radius0.45
threshold0.55

通常のUnrealBloomPass。輝度がthresholdを超えた画素だけが光る （個別レイヤーではなく画面全体の輝度基準）。

Post FX

monochrome0.00

表示直前の最終色をグレースケールに寄せる（0=カラーのまま、1=完全モノクロ）。 bloomの輝度判定はカラーのまま行われた後にこれが最後に掛かるので、光り方には影響しない。

カメラは固定（Phase 2で深度ディスプレイスメント＋移動を追加予定）。 マッピングは config/midi-mapping.json を読み込む。

左のパネルから写真を読み込むか、「サンプルを読み込む」で試してください。
SEQTRAKでKICKを鳴らすと、輝度マップの場所が一律に明滅します。
