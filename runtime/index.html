Night Light VJ

Phase 1

写真の輝度マップに応じて、写真そのものの明るさをMIDIトラックに連動させて上げ下げする。個別の光点は打たず、検出した場所を4クラスタに振り分けてトラックごとに明滅させる。疑似深度によるディスプレイスメントとカメラの呼吸移動あり（Phase 2、実験的）。

Scene

写真を読み込むと、輝度の高い場所（ネオン等）から輝度マップを自動生成する（下の Auto Extract 参照）。 画像はブラウザ内だけで処理され、どこにも送信されない。

Auto Extract（輝度マップの自動生成）

top %（明るい上位何%をマップに含めるか）15.0

検出: -

画素ごとに直接、輝度をそのまま重みにしてマップに書き込む（塊検出はしない）。 検出した画素は画面のY位置だけで4クラスタ(0-3)に振り分ける（下ほど手前＝ cluster0、上に行くほど番号が大きくなる）。各クラスタは config/midi-mapping.json の同じ cluster 番号を持つ cluster_trigger トラックに連動する。 mask-editor/ で作った points.json を下の欄で読み込むと、 自動抽出の代わりにその点群（各点のcluster指定つき）からマップを作る。

MIDI Input

Web MIDI へのアクセスを要求しています…

Cluster Envelopes

実際にNote Onを受信したのと同じ処理を呼ぶ（velocity=100、name="KICK"のトラック ＝cluster0向け）。SEQTRAKが無くても、MIDI受信側の問題か描画側の問題かを 切り分けられる。これを押してメーターだけ動いて画面が変化しなければ描画側、 これでも画面が変化するのに実機のKICKで変化しなければMIDI受信側 （config/midi-mapping.jsonのchannel/noteが実機と不一致等）を疑う。

Brightness

bright gain（明滅の強さ）1.20
base level（待機中の沈み）0.00

輝度マップの値が乗っている場所だけ、対応するクラスタのMIDIノートに応じて 元の写真の明るさを上げる（マップが0の場所は写真のまま変化しない）。 base level をマイナスにすると、マップが乗っている場所は待機中は 元の写真より暗く沈み、そのクラスタのノートが来たときだけそこから明るく 持ち上がるようになる（0なら待機中は写真のまま静止）。 ambient breathing（MIDIが無い間の自動揺らぎ）は検証を単純化するためいったん オミットしている。

Bloom

strength1.60
radius0.45
threshold0.55

通常のUnrealBloomPass。輝度がthresholdを超えた画素だけが光る （個別レイヤーではなく画面全体の輝度基準）。

Depth 3D（Phase 2・実験的）

depth strength（ディスプレイスメントの強さ）0.60
dolly amplitude（カメラの振幅）0.30
dolly period（呼吸の周期・秒）8.00

本物の深度推定モデルはこの環境には無いため、画面のY位置（下ほど手前）と輝度 （明るい場所はわずかに手前）から作る簡易的な「疑似深度マップ」で代用している。 背景メッシュを細分化し、疑似深度ぶんだけ頂点Zをずらして視差を作り、 カメラをZ方向にゆっくり前後させる（dolly_in、要件定義書 §7）。 振幅を上げすぎると疑似深度の粗さや破綻（塗りつぶし領域の境界など）が 見えやすくなるので、小さめの値が基本（要件定義書 §11「深度の破綻はカメラ振幅で 隠す」）。トグルを外すと頂点Zもカメラも静止し、Phase 1と同じ平面の見た目に戻る。 MIDI Clockへの位相同期は未実装（今は時間ベースの一定周期）。

Post FX

monochrome0.00

表示直前の最終色をグレースケールに寄せる（0=カラーのまま、1=完全モノクロ）。 bloomの輝度判定はカラーのまま行われた後にこれが最後に掛かるので、光り方には影響しない。

マッピングは config/midi-mapping.json を読み込む。

SEQTRAKで各トラックを鳴らすと、対応するクラスタの輝度マップの場所が明滅します。 カメラは疑似深度に沿ってゆっくり前後に呼吸します（Depth 3Dパネルで調整可）。
