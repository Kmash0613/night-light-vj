# ランタイム（Three.js）

要件定義書 §5, §9 参照。

## Phase 1（実装済み・実機での確認待ち）

写真1枚で、MIDI Note On による光点の加算合成明滅を確認する。カメラは固定（移動なし）。
ブルームは光点レイヤーのみに適用され、背景写真にはかからない
（three.js の selective bloom = "darken non-bloomed" 手法。`main.js` 参照）。

- Three.js は `index.html` の importmap で CDN (unpkg) から読み込む。ビルド不要
- `../config/midi-mapping.json` を起動時に `fetch` する。`file://` では動かないため、
  ローカルサーバー経由（`python -m http.server`）か GitHub Pages 経由で開くこと
- 写真・光点データは `<input type="file">` でローカル読み込みし、どこにも送信しない

### 光点の自動抽出

写真を読み込むと、要件定義書 §4 の「光点抽出」「クラスタリング」の簡易版をブラウザ内で
その場で実行する（Python側のバッチツールはまだ無いため、Phase 1用の暫定実装）。

1. 輝度（0.2126R+0.7152G+0.0722B）を計算し、上位 `top %` の明るいピクセルを閾値化
2. 4連結の連結成分ラベリングでピクセル塊（光点）に分解し、`min area` 未満のノイズを除去
3. 面積の大きい順に `max points` 個までに間引く（要件定義書の上限2000点を参考にデフォルト700）
4. クラスタ分け: **深度推定がまだ無い（Phase 2）ため、「画面下ほど手前・面積が大きいほど手前」
   という簡易ヒューリスティックで代用**し、`clusters` 個のグループに分割する。
   cluster 0 = 最前景（`config/midi-mapping.json` の規約に合わせる）

「Auto Extract」パネルの「再抽出」でパラメータを変えて再実行できる。結果は
「points.json を書き出し」で保存でき、`mask-editor/` に読み込んで手動で調整することもできる
（逆に `mask-editor/` で作った `points.json` を読み込めば自動抽出を上書きできる）。

### 明滅・呼吸

- 明滅エンベロープ: `env = velocity/127 * exp(-t/tau)`。クラスタは複数トラックが乗る場合、
  各トラックのエンベロープの最大値をそのクラスタの値として採用する
- MIDIが鳴っていない間もゼロにはならず、点ごとに位相をずらしたアンビエントな明滅
  （「呼吸する街」§1）をベースに乗せ、MIDIがその上に加算される。「Light Points」パネルの
  `ambient breathing` スライダーで量を調整（0でMIDIのみの明滅に戻る）
- 元の写真自体の輝度も、明るい場所ほど強くゆっくり明滅する（「Background」パネルの
  `luminance sway`）。UV座標のハッシュを位相にしているため場所ごとにバラバラに明滅する

### 色まわり

- `renderer.toneMapping` は `NoToneMapping`。背景写真のマテリアルに `toneMapped: true`
  （デフォルト）のままフィルミックトーンマッピングをかけると `OutputPass` のカラーマネジメントと
  二重適用され彩度・コントラストが落ちるため使わない
- 背景は独自の `ShaderMaterial`（輝度ゆらぎのため）。テクスチャは手動で sRGB→linear変換してから
  ゆらぎを掛け、`OutputPass` が最後に linear→sRGB に戻す
