# ランタイム（Three.js）

要件定義書 §5, §9 参照。

## Phase 1（実装済み・実機での確認待ち）

写真1枚で、MIDI Note On による輝度の明滅を確認する。カメラは固定（移動なし）。

**設計方針: 個別の光点（パーティクル）は打たない。** 写真から「輝度マップ」（重み画像）を作り、
MIDIノートに応じてそのマップの値が乗っている場所だけ、元の写真そのものの明るさを上げ下げする。
マップが0の場所（暗い背景など）は変化しない。

**クラスタは最大4つ（0-3）。** 輝度マップはRGBAの4チャンネルテクスチャで、各チャンネルが
1クラスタの重みに対応する。`config/midi-mapping.json` の `cluster_trigger` トラックは
`cluster` フィールド（0-3）で自分の紐づく先を決め、Note Onが来るとそのクラスタの重みが
乗っている場所だけ明るさが上がる。一度、動作確認を単純化するためクラスタ分けを丸ごと無くし
KICK一本にしていたが、明滅の土台が安定して確認できたので復活させた
（cluster不明のエントリはcluster0にフォールバックする）。

### 出力フレーム（16:9固定・コンテインフィット）

レンダラー・カメラのフラスタムは常に16:9固定（`OUTPUT_ASPECT` in `main.js`）。
写真の縦横比がそれと違っても、写真自体は歪ませず（メッシュのスケールは常に等倍）、
"contain" fit（CSSの`background-size:contain`と同じ）で16:9フラスタム内に必ず全体が
収まるように縮小する。クロップは一切発生せず、横長の写真は上下に、縦長の写真は左右に
黒帯が出る。ブラウザのウィンドウ/パネル幅が16:9と違う形でも、レンダラーのサイズ自体を
その中に収まる最大の16:9矩形に決めるので（`resize()`）、その分も含めて余りは全部
`#viewport`の黒帯になる。

### 輝度マップの生成（要件定義書 §4 の簡易版・ブラウザ内実装）

写真を読み込むと自動で実行される（`extractLuminanceMask()` in `main.js`）。

1. 輝度（`0.2126R+0.7152G+0.0722B`）を計算し、上位 `top %` の明るいピクセルの閾値を求める
2. **画素ごとに直接**、閾値を超えた画素だけ「その画素自身の輝度 / 255」（最低0.35）を
   重みとして書き込む。書き込み先のチャンネル（＝クラスタ）は、その画素のY位置だけで
   決める簡易的な「奥行きの代用」: 画面下ほど手前＝cluster0（Rチャンネル、config側の
   KICK=cluster0の慣習に合わせる）、上に行くほど番号の大きいクラスタ（G→B→A）になる

以前は4連結の連結成分ラベリングで塊（領域）を作り、塊ごとに「閾値からの超過量」を重みに
していたが、この方式は**閾値の位置によって0除算的に重みが全て0になる**（白飛びが多い写真で
閾値が255に張り付くと、閾値を超える画素は必ずluma===255なので超過量が常に0になる）ことや、
**塊がたまたま画像の広い範囲を覆ってしまう**ことが繰り返し起きた。重みを画素自身の輝度で
決める今の方式は threshold の位置に関係なく数学的に0除算にならず、`targetCount <= 総画素数`
が保証される以上「該当画素が0個で輝度マップが空になる」ことも起こり得ない。

「Auto Extract」パネルの「再抽出」で `top %` を変えて再実行できる。
`mask-editor/` で作った `points.json` を読み込むと、各点を中心にソフトな円を同じ形式へ
スタンプしてマップを作る（自動抽出の代わりに手動データを使いたいとき用）。

**過去に踏んだバグ（修正済み）:**

1. 輝度マップを書き込む `canvas` のアルファチャンネルを0のまま（`createImageData` の初期値）
   にしていたため、ブラウザのcanvas内部実装（premultiplied alpha）が `putImageData`/
   `getImageData` の往復や `THREE.CanvasTexture` としてWebGLへアップロードする際に、
   アルファ0の画素のRGBを丸ごと0に潰していた。結果、重みマップは常に「重み0」しか
   持てず、KICKが来ても写真の明るさが一切変化しない状態になっていた
   （当時は全画素のアルファを255にする回避策で対処したが、下記3.で根本的に解消）。
2. 上位 `top %` の閾値をヒストグラム（丸めた輝度でバケット化）から求めているのに、実際に
   画素を採用するかどうかの判定は丸めていない生の輝度値と比較していたため、単色に近い
   塗りつぶし領域（建物のシルエットなど）の輝度が閾値のすぐ下の小数（例: 33.7）だと、
   丸めればヒストグラム上はカウントされるのに実際のフィルタでは弾かれ、指定した `top %`
   よりはるかに少ない画素しか検出されないことがあった（`luma[]` 自体を丸めた整数として
   保持することで解消）。
3. クラスタ復活でアルファチャンネル自体がcluster3の実データになったため、上記1.の回避策
   （アルファを255固定にする）が使えなくなった。根本原因は「2Dキャンバス経由でWebGL
   テクスチャを作ると、ブラウザ内部のpremultiplied alpha実装に引っかかりうる」ことなので、
   `<canvas>`/`CanvasTexture` を経由するのをやめ、生の `Uint8Array` から直接
   `THREE.DataTexture` を作る方式に変更した。`texImage2D` へ生バイト列がそのままアップ
   ロードされるだけで、canvasの内部表現も `putImageData`/`getImageData` の往復も一切発生
   しないため、4チャンネルとも安全にデータとして使える（`makeMaskTexture()` in `main.js`）。

### 明滅（背景シェーダー内で完結）

背景メッシュは独自の `ShaderMaterial`（`map`=元の写真, `maskMap`=RGBA4チャンネルの輝度マップ）。
フラグメントシェーダーで、写真の各画素の明るさに
`factor = 1 + brightGain * (totalWeight * baseLevel + dot(w, clusterEnvelope))` を掛ける
（`w` はその画素のマップ値=vec4、`totalWeight` はその合計をclampしたもの、
`clusterEnvelope` は4クラスタ分のエンベロープをまとめたvec4）。

- クラスタエンベロープ: `env_c = velocity/127 * exp(-t/tau)`。クラスタ `c` にマッチする
  トラックが複数あれば最大値を採用する（CPU側で計算しシェーダーへvec4のuniformで渡す）
- `bright gain` は明滅の強さ全体のゲイン
- `base level` は待機中（どのクラスタも鳴っていないとき）の定数ベースライン。0以下の
  スライダーで、マイナスにするとマップが乗っている場所は待機中は元の写真より暗く沈み、
  そのクラスタのノートが来たときだけそこから明るく持ち上がる。0なら待機中は写真のまま
  静止する（従来通り）。

**ambient breathing（MIDIが無い間の自動揺らぎ、0を中心に上下する符号付きサイン波）は
検証を単純化するためいったんオミットしている。** 過去に踏んだバグでトリガー自体が
機能しているかどうかの切り分けが難しかったため、まずクラスタのNote Onだけで明滅することを
確認できるプリミティブな構成に戻した。`base level` は定数オフセットのみで揺らぎは無い、
その簡易版にあたる。安定して確認できたら、ambient breathingの方は再度追加する。

### ブルーム

selective bloomではなく通常の `UnrealBloomPass`（画面全体の輝度がthresholdを超えた画素が光る）。
クラスタのノートで明るくなった場所（またはもともと明るい場所）がしきい値を超えれば自然に光る。
「Bloom」パネルのスライダーで調整（SEQTRAKのFX LEVEL CCでも `strength` を操作可能）。

### Post FX（モノクロ）

`EffectComposer` の最後（`OutputPass` の後）に `ShaderPass` でモノクロ化を1枚挟んでいる。
bloomの輝度判定はその手前でカラーのまま行われるので、光り方には影響しない。
「Post FX」パネルの `monochrome` スライダー（0=カラーのまま、1=完全モノクロ）で調整する。

### 色まわり

- `renderer.toneMapping` は `NoToneMapping`。背景シェーダーは手動で sRGB→linear変換してから
  明るさを掛け、`OutputPass` が最後に linear→sRGB に戻す（二重トーンマッピングを避ける）

### その他

- Three.js は `index.html` の importmap で CDN (unpkg) から読み込む。ビルド不要
- `../config/midi-mapping.json` を起動時に `fetch` する。`file://` では動かないため、
  ローカルサーバー経由（`python -m http.server`）か GitHub Pages 経由で開くこと
- 写真・光点データは `<input type="file">` でローカル読み込みし、どこにも送信しない
