# 夜景写真VJシステム 要件定義書

## 1. 概要

夜景写真から抽出した光点を、YAMAHA SEQTRAK から送られる MIDI に同期して明滅させる。
写真は単眼深度推定によって疑似3D化し、その空間内を仮想カメラが移動することで奥行きのある映像を生成する。

**コンセプト**：静止画である夜景写真を、音楽に呼応して「呼吸する街」として再生する。

---

## 2. スコープ

### 含むもの
- 写真の前処理バッチツール（深度推定・光点抽出・メタデータ生成）
- リアルタイム描画ランタイム
- SEQTRAK との MIDI 連携
- カメラパスの完全自動生成

### 含まないもの（今回は作らない）
- スクリーンセーバー化、`.scr` 化、Wallpaper Engine 対応
- システム音声のループバック取得、FFT によるビート検出
- Spotify 等の外部音楽サービス連携
- カメラパスの手動編集UI（将来的な拡張候補）
- Resolume 等への映像送出（将来的な拡張候補）

---

## 3. 実行環境

| 項目 | 内容 |
|---|---|
| OS | Windows |
| SEQTRAK 接続 | USB-C 有線のみ（Windows では Bluetooth MIDI 不可） |
| ランタイム | Chrome（Web MIDI API 使用） |
| 描画 | Three.js / WebGL2 |
| バッチ | Python 3.11 |
| GPU | 深度推定に CUDA 利用可能なら望ましい（必須ではない） |

### 事前準備
- Yamaha Steinberg USB Driver のインストール
- loopMIDI による仮想MIDIポートの用意（Windows のポート排他対策）

## 4. コンポーネントA：バッチ前処理ツール（Python）

**本プロジェクトの工数の大半を占める。素材を1枚追加する操作が完全に自動で完結することを最重要要件とする。**

### 入力
- 夜景写真 数十枚（JPEG / PNG、任意の解像度・アスペクト比）
- 配置場所：`input/`

### 処理パイプライン

1. **正規化**
   - 長辺 2048px にリサイズ、EXIF 回転を適用
   - アスペクト比はメタデータに保持（クロップしない）

2. **深度推定**
   - Depth Anything V2 を使用
   - ライセンス要確認（モデルサイズによりライセンスが異なる）
   - 出力は相対深度。16bit PNG で保存

3. **深度の後処理**
   - バイラテラルフィルタでノイズ除去（エッジは保持）
   - 空領域の検出と最遠方への固定（上部かつ低テクスチャ領域）
   - 深度ヒストグラムの統計量を算出（後段のカメラパス選択に使用）

4. **光点抽出**
   - 輝度チャンネルに対する閾値処理（初期値：上位2〜5%）
   - 連結成分ラベリングで個別の光点に分解
   - 微小ノイズ（面積 N px 未満）を除去
   - 各光点の重心座標・面積・平均色・深度値を記録

5. **クラスタリング**
   - 光点を 3〜5 群に分割
   - クラスタリング軸：**深度を主、画面上のXY座標を従**とする
     （手前のネオンと奥の窓明かりが別群になることが狙い）
   - 各クラスタの代表深度・光点数・平均色を記録

6. **カメラパステンプレート選択**
   - 深度統計からルールベースで選択（詳細は §7）

7. **品質フラグ**
   - 深度の破綻が疑われる写真に警告フラグを立てる
   - 判定材料：深度のレンジが極端に狭い、空領域の割合が異常、光点数が過少または過多
   - **フラグ付きの写真は自動的に除外せず、目視確認用のコンタクトシートに出力する**

### 出力

```
scenes/
  <scene_id>/
    color.jpg      # 正規化済みカラー画像
    depth.png      # 16bit 深度マップ
    mask.png       # 光点マスク（クラスタIDをチャンネルに符号化）
    meta.json
  _contact_sheet.jpg   # 全シーンのサムネイル＋深度の並列表示
  index.json           # 全シーンの一覧
```

### meta.json スキーマ（案）

```json
{
  "scene_id": "night_0007",
  "source": "DSC_0421.jpg",
  "resolution": [2048, 1365],
  "depth_stats": {
    "range": 0.82,
    "median": 0.41,
    "sky_ratio": 0.23,
    "foreground_ratio": 0.15
  },
  "clusters": [
    {
      "id": 0,
      "point_count": 142,
      "mean_depth": 0.15,
      "mean_color": [255, 180, 90],
      "centroid": [0.42, 0.61]
    }
  ],
  "camera": {
    "template": "dolly_in",
    "amplitude": 0.6,
    "look_at": [0.5, 0.45]
  },
  "quality_flags": [],
  "dominant_colors": [[255, 180, 90], [120, 160, 255]]
}
```

## 5. コンポーネントB：ランタイム（Three.js）

### アセット管理
- `index.json` を起動時に読み込み、シーン一覧を構築
- **前後2シーンを先読みするリングバッファ**。全アセットの同時展開は行わない
- 切り替え時のロード待ちを隠すため、クロスフェード中に次を読む

### シーン構成
- **背景メッシュ**：深度マップによるディスプレイスメントを適用した平面
- **光点レイヤー**：抽出した光点をクラスタ単位のパーティクル群として配置（Z座標は深度由来）
- **カメラ**：PerspectiveCamera。パスに沿って移動

### 描画パス
1. 背景メッシュの描画
2. 光点の加算合成（クラスタごとに独立したエンベロープ値を乗算）
3. ブルーム（光点レイヤーのみを対象）
4. 被写界深度（フォーカス距離は MIDI CC で可変）
5. カラーグレーディング

### 明滅エンベロープ
- ノートオンで即座に立ち上げ、指数減衰：`env = exp(-t / tau)`
- `tau` の初期値：0.15秒（トラックごとに個別設定可能）
- ベロシティを振幅に乗算

## 6. MIDI 仕様

### 入力（SEQTRAK → PC）

| MIDI メッセージ | 用途 |
|---|---|
| Clock (24ppq) | 拍・小節位置の算出。カメラパスの位相決定 |
| Start / Stop | シーンのリセット、再生状態の制御 |
| Song Position Pointer | 位相の同期 |
| Note On（トラック別） | 光点クラスタのトリガー |
| Velocity | エンベロープ振幅 |
| CC（FX LEVEL / HIGH PASS / REPEATER） | ブルーム量・DOF焦点距離・カメラ振幅 |

### マッピング初期案（**要実測**）

| SEQTRAK トラック | 割り当て |
|---|---|
| KICK | クラスタ0（最前景）＋カメラのズームキック |
| SNARE | クラスタ1 |
| HIHAT / PERC | クラスタ2〜3（遠景の細かい光点） |
| SYNTH 1 / 2 | 全体の色相シフト |
| DX | ブルーム強度のスパイク |
| SAMPLER | シーン切り替えトリガー（候補） |

**マッピングはハードコードせず、JSON 設定ファイルとして外出しする。** ノート番号とチャンネルは実機で計測して確定させる。

### 遅延補正
- 映像側の遅延を ±100ms の範囲で調整できるスライダーを設ける
- MIDI ノートは音の発音よりわずかに先行するため、通常は正方向の補正のみで足りる想定

## 7. カメラパス自動生成

### テンプレート

| テンプレート | 適用条件 | 動き |
|---|---|---|
| `dolly_in` | 奥行きレンジが広い | 前後方向のゆっくりした移動 |
| `lateral_pan` | 前景の占有率が高い | 横移動。視差が最も強く出る |
| `orbit` | 中央に主要被写体がある | 注視点を中心に緩く旋回 |
| `crane` | 空の割合が大きい | 上下移動 |

選択はルールベース。深度統計から決定木で分岐する。

### 時間軸の階層

| 階層 | 周期 | 内容 |
|---|---|---|
| マクロ | 8小節 | テンプレートに沿った連続的な移動。ループする |
| ミクロ | 拍単位 | キックによるズームの瞬間的な加算 |
| カット | 16小節 or トリガー | シーン切り替え |

**マクロは常に動き続け、ミクロはそこに加算される**。全てをビートに同期させると視覚的に疲れるため、ベースは滑らかに保つ。

### 振幅の制約
深度推定の破綻を露出させないため、カメラの移動量には上限を設ける。`meta.json` の `amplitude` は品質フラグに応じて自動的に抑制する。

## 9. 実装フェーズ

**Phase 0：MIDI 実測**
Web MIDI で SEQTRAK からの全メッセージをログ出力するだけのツール。各トラックのノート番号・チャンネル・CC番号を確定させ、マッピング設定ファイルの初版を作る。
→ *ここが終わらないと他の設計が確定しないため、最優先*

**Phase 1：光点明滅の最小構成**
写真1枚、手作業で作った光点マスク、カメラ動きなし。MIDI ノートで加算合成が明滅することを確認する。ブルームの見え方をここで詰める。

**Phase 2：深度による3D化**
深度マップを手動で1枚用意し、ディスプレイスメントとカメラ移動を実装。振幅の限界値を実測で見極める。

**Phase 3：バッチツール**
Phase 1〜2 で手作業していた部分を自動化。コンタクトシートで品質を確認できる状態にする。

**Phase 4：ライブラリ化**
数十枚のシーン管理、先読み、切り替え演出、カメラパスの自動選択。

## 11. 設計上の原則

1. **推定より確定情報を使う。** MIDI から取れる情報は、音声解析で推定しない。
2. **前処理はすべて自動化する。** 手作業が1ステップでも残ると、素材が増えなくなる。
3. **深度の破綻はカメラ振幅で隠す。** モデルの精度向上より、動きの設計で回避するほうが安上がり。
4. **マッピングは設定ファイルに外出しする。** 実機の挙動は実測でしか分からない。
